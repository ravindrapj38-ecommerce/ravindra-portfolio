# Decisions log

Defaults chosen where the spec left room. Newest last. Format: context → decision → why.

## D-001 · Project location inside the portfolio repo (Phase 0)
The repo `ravindra-portfolio` already hosts other projects (`glidecast/`, root `index.html`).
**Decision:** the whole monorepo lives in `veritext-stem/`. CI workflows sit at the repo root
(`.github/workflows/veritext-*.yml`, a GitHub requirement) and are path-filtered to
`veritext-stem/**`. Easy to lift into its own repo later (`git subtree split`).

## D-002 · Python workspace layout
**Decision:** a uv *workspace* rooted at `veritext-stem/pyproject.toml` with members
`services/engine` (package `veritext_engine`) and `benchmarks/stem_fidelitybench`
(package `stem_fidelitybench`). One lockfile, one venv.
The spec's `services/engine/pipeline/` maps to `services/engine/veritext_engine/pipeline/`
(a top-level package literally named `pipeline` would collide with other distributions).
Prompts stay at `services/engine/prompts/` as data files, as specified.

## D-003 · Heavy ML dependencies are optional extras
`torch`/`transformers` (DeBERTa NLI) and `spacy`/`scispacy` + `en_core_sci_md` are large.
**Decision:** they live in the engine's `nlp` optional extra. Core install + CI unit tests run
without them; stages that need them depend on a protocol and fall back with an explicit
"check unavailable → needs review" status (never a silent pass). A separate CI job installs
the extra once Phase 2 lands.

## D-004 · Auth provider: Auth.js (not Clerk)
Self-hostable, no per-MAU vendor fees, works fully offline in `docker compose`, and keeps
identity data in our Postgres — simpler for data-residency/enterprise SSO later.
Wired up in Phase 5.

## D-005 · Health endpoints
`GET /healthz` = liveness (process up, no dependency calls).
`GET /readyz` = readiness; probes Postgres, Redis and S3 with short timeouts and returns 503
if any is down. Web exposes `GET /api/health` reporting itself plus engine readiness.

## D-006 · Local S3 = MinIO
Compose runs MinIO with a one-shot `mc` container that creates the uploads bucket with a
1-day expiry lifecycle rule (zero-retention default; saved projects are copied to a separate
prefix in Phase 5).

## D-007 · Observability
structlog with JSON output (console renderer when `VERITEXT_LOG_FORMAT=console`).
OpenTelemetry tracing is configured only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set, so local
runs and tests have zero exporter overhead.

## D-008 · Placeholder token syntax
`⟦<KIND><n>⟧` with single-letter kinds: M math, N number/unit, C citation, R cross-reference,
K code, E scientific entity, G glossary term, A acronym, U URL/DOI. Brackets U+27E6/U+27E7 are
virtually absent from real STEM text; the protect stage escapes any pre-existing occurrence so
the round-trip stays the identity.

## D-009 · Prompt files
`prompts/<name>/v<N>.md` with YAML front matter + body, plus `prompts/<name>/eval.yaml`.
The registry refuses to load a prompt without an eval file, which enforces the
"every prompt has an eval case" rule mechanically.

## D-010 · Web stack details
Next.js 15 App Router, React 19, Tailwind CSS v4 (CSS-first config), shadcn/ui "new-york" style
via `components.json` (components are added per need with the shadcn CLI). Vitest for unit
tests, Playwright for e2e (CI installs Chromium; local cloud sessions use the preinstalled one).
Monaco/KaTeX/diff are Phase 3 dependencies, not added yet.

## D-011 · First milestone checks are rule-based (Milestone 1)
The spec's verify stage includes NLI and an LLM judge. **Decision:** the first version ships
deterministic sentence checks only: locked-item multiset, unlocked numbers and number words, hedge
class (hedged / neutral / boosted / mixed), causal vs correlational cues, negation parity, and
citation attachment (each citation keeps at least one of the three content stems it followed).
Soft checks (content-word drift < 40 %, length ratio outside 0.5–1.8) give "needs review".
They are deliberately conservative: a false alarm costs a retry or keeps the original sentence;
it never lets a changed claim through. NLI / judge / claim extraction stay in Phase 2.

## D-012 · One source of truth for rules, shared by Python and TypeScript
Lock patterns (`shared/lock_patterns.json`, generated by `scripts/gen_lock_patterns.py`), cue
lexicons, overused phrases, demo substitutions and the sample live in `shared/`. Patterns use only
syntax both `re` and JS `RegExp` accept. `fixtures/protect_cases.json` and `check_cases.json` run in
both test suites, and `fixtures/golden_demo_reports.json` (from `scripts/gen_golden.py`) makes the web
core prove it produces byte-identical reports to the engine.

## D-013 · A TypeScript port of the pipeline runs in the browser
The FastAPI engine is authoritative. `apps/web/lib/core` is a port used for (a) the published preview,
which cannot call a server, and (b) a fallback when the engine is down. Parity is enforced by D-012's
golden fixture, so a change to either side fails CI until both match.

## D-014 · Pluggable rewrite provider
`VERITEXT_PROVIDER=auto` uses Claude (`ANTHROPIC_API_KEY`, model from `VERITEXT_MODEL_REWRITE`) when a
key is set, else the offline demo rewriter (phrase substitutions that never touch hedge, causal or
negation cues). The demo is labelled as such in the UI and API. The preview artifact uses the
artifact runtime's `sample` capability, so it rewrites with Claude on the viewer's own account.

## D-015 · One rewritten sentence per input sentence
The rewriter gets a paragraph's sentences and must return the same number, in order. This keeps
per-sentence verification and "keep the original" simple. A misaligned batch is retried sentence by
sentence. Merging/splitting sentences can come later with claim-level alignment.

## D-016 · Fidelity score
Word-weighted mean over prose sentences: verified = 100, kept original = 100 (the original meaning
ships), needs review = 100 − 20 per soft issue (floor 50). The UI shows it next to "text rewritten"
(share of words in sentences that actually changed), so a run that kept everything is visibly not a
rewrite. Half-up rounding in both languages.

## D-017 · Preview hosting
The build environment cannot reach Vercel or similar hosts. **Decision:** the preview is the
single-file build (`pnpm --filter web build:preview`) published as a private claude.ai artifact.
A real deployment (Vercel for web, a container host for the engine) is a later milestone.

## D-018 · Engine is a single uv project for now
D-002's uv workspace waits for the benchmark package. Until then `services/engine` is its own uv
project, and the web app is the only pnpm workspace member.
